## Ringkasan (≤ 5 kalimat)
Paket A4 membangun rangkaian pengujian otomatis ujung-ke-ujung (*end-to-end*) Playwright (30 tes di 5 berkas spesifikasi), perbandingan regresi visual lintas-platform, audit aksesibilitas `axe-core` WCAG 2.1 AA (0 pelanggaran `serious`/`critical`), dan konfigurasi anggaran Lighthouse CI di atas fixture klinik sintetis lokal (`http://127.0.0.1:54321`) tanpa pernah menyentuh produksi maupun kunci rahasia. Seluruh permintaan jaringan ke Supabase Auth/REST/RPC/Edge Functions dan Google Fonts dicegat di lapisan `page.route` sehingga eksekusi 100% kedap jaringan luar dan stabil **5× berturut-turut (`150/150` tes hijau, 0 flaky, ~1,6 menit/putaran)**. Selama audit E2E & `axe-core`, ditemukan dan diperbaiki 3 bug runtime nyata (`PaymentList.jsx`, `SchedulePage.jsx`, `LoginPage.jsx` + normalisasi pesan galat generik) serta peningkatan kontras warna WCAG AA $\ge 4.5:1$ dan label ARIA di 8 komponen. Perubahan di `apps/clinic/src/components/ai/**` dibatasi murni pada kelas gaya kontras Tailwind tanpa mengubah atau menambah logika agen sedikit pun.

## Keputusan desain & alasan
1. **Stabilitas Baseline Regresi Visual Lintas-Platform (Windows Lokal & Linux CI):**
   - **Masalah:** Mesin perender font (DirectWrite di Windows vs FreeType di Ubuntu/Linux CI) menghasilkan perbedaan sub-piksel anti-aliasing pada huruf, serta Playwright secara bawaan menggagalkan pengujian jika berkas baseline berakhiran `-linux.png` belum ada di git.
   - **Solusi Tiga Lapis di `playwright.config.js` & `visual-a11y.spec.js`:**
     1. **Akhiran Platform (`snapshotPathTemplate: '{testDir}/__screenshots__/{arg}-{platform}{ext}'`):** Setiap tangkapan layar disimpan per sistem operasi (`*-win32.png` di Windows, `*-linux.png` di Linux CI). Seluruh 12 berkas baseline `*-win32.png` telah di-commit di `apps/clinic/tests/e2e/__screenshots__/`.
     2. **Fallback Lintas-OS Otomatis Tanpa Gagal Berkas Hilang:** Di `visual-a11y.spec.js`, sebelum memanggil `expect(page).toHaveScreenshot(filename)`, tes memeriksa apakah baseline native platform (`${baseName}-${process.platform}.png`, mis. `*-linux.png` di runner Ubuntu) sudah tersedia. Bila belum ada di git, tes menyalin baseline referensi `*-win32.png` sebagai pembanding awal dan menyimpan tangkapan layar asli Linux (`*-linux.png`) ke `docs/tim/serah-terima/A4/visual/` (yang diunggah sebagai artefak CI di `docs/tim/usulan-ci/e2e.yml` sehingga dapat langsung di-commit).
     3. **Toleransi Piksel Adaptif (`maxDiffPixelRatio` & `threshold`) + Pencegahan Jaringan Font:**
        - Seluruh permintaan `fonts.googleapis.com` & `fonts.gstatic.com` dicegat lokal dan animasi dimatikan (`animations: 'disabled'`, `reducedMotion: 'reduce'`).
        - Bila membandingkan pada platform yang sama (`hasNativePlatformBaseline === true`), berlaku toleransi ketat **`maxDiffPixelRatio: 0.02` (2%) dan `threshold: 0.2`**.
        - Bila membandingkan lintas-OS pada eksekusi CI Linux pertama (`hasNativePlatformBaseline === false`), berlaku toleransi **`maxDiffPixelRatio: 0.06` (6%) dan `threshold: 0.3`** yang cukup untuk menyerap perbedaan anti-aliasing huruf DirectWrite vs FreeType pada viewport `1440×900` dan `375×812` tetapi tetap menangkap regresi tata letak, warna, atau komponen yang hilang.
2. **Penggunaan Build Mode Desktop (`vite build --mode desktop`) tanpa Service Worker:**
   - **Alasan:** Pada build standar produksi, `VitePWA` mendaftarkan Service Worker (`sw.js`) yang mem-precache 84 aset dan mencegat jaringan di level browser serta menyimpan cache lintas pengujian. Dengan `--mode desktop` (`VITE_DESKTOP=1`), registrasi Service Worker dinonaktifkan sehingga pencegatan `page.route()` Playwright selalu deterministik 100% dan bebas kebocoran state antar-tes.
3. **Pesan Galat Login Generik (`LoginPage.jsx`):**
   - Untuk mencegah *user enumeration* (penyerang mengetahui apakah suatu alamat email terdaftar di klinik atau tidak), `LoginPage.jsx` menormalisasi seluruh pesan galat autentikasi/kredensial menjadi pesan tunggal `'Email atau password salah.'`. Perilaku ini diuji secara eksplisit di `auth.spec.js` menggunakan skenario email tidak terdaftar (`tidak-terdaftar@klinik-sintetis.test`) dan skenario email terdaftar dengan sandi salah (`admin@klinik-sintetis.test` + `PasswordSalah999!`).

## Risiko, batasan, dan hal yang belum selesai
1. **Hal yang TIDAK Teruji Akibat Penggunaan Build Mode Desktop (`--mode desktop` / Tanpa Service Worker):**
   - **Siklus Hidup Service Worker & PWA Web (`sw.js` / `registerSW.js`):** Pendaftaran Service Worker, *precache manifest* (`workbox-*.js`), dan mekanisme pembaruan cache saat versi baru di-deploy di web tidak ikut diuji di dalam suite E2E ini.
   - **Mode Luring (*Offline Fallback* PWA di Peramban):** Kemampuan halaman web memuat aset dari Cache Storage saat koneksi internet terputus tidak teruji oleh E2E ini.
   - **Elemen UI Khusus Web Non-Desktop (`!isDesktop`):** Cabang tampilan yang hanya muncul ketika `isDesktop === false` — seperti tautan *"Unduh aplikasi desktop untuk Windows & macOS"* di bagian bawah `LoginPage.jsx` — disembunyikan selama E2E karena `VITE_DESKTOP=1`.
2. **Pemasangan Workflow CI:** Berkas workflow GitHub Actions disimpan sebagai usulan di `docs/tim/usulan-ci/e2e.yml` sesuai aturan kepemilikan area (`.github/workflows/**` milik Ketua).
